# 证件照生成器（ID Photo）

纯前端证件照制作工具。上传照片 → 拖动构图 → 点「预生成」→ 下载，全过程在浏览器本地完成，**照片不上传任何服务器**。

- 线上地址：https://id-photo-3kh.pages.dev
- 仓库：https://github.com/peidongl98/id-photo

> 交互为**「预生成 / 重新裁剪」双态**：上传后先静默完成人脸与轮廓分析（不显示裁剪框），
> 分析完才出取景框；拖动只移动取景框、不做任何图像处理，点「预生成」才出效果。
> 结果缓存在内存里，调背景色 / 磨皮会复用中间结果快速重算，**全程只跑一次 MODNet**。

## 功能

| 模块 | 说明 |
|---|---|
| 启动页 | 每次访问都显示；两个模型并行下载 + 实时进度 + 阶段文字；最短 1 秒；失败可重试 3 次 |
| 上传 | 未上传时显示区是大虚线上传框（点击 / 拖拽 / 粘帖 / 手机拍照）；JPG、PNG、HEIC；按 EXIF 方向自动摆正 |
| 分析阶段 | 上传后静默跑：Face Landmarker 468 点 → MODNet 整图 alpha matte → 扫出发际线以上的头顶 → 算裁剪框；期间按钮禁用、参数锁定 |
| 裁剪视图 | 原图 + 半透明取景框；拖动 / 滚轮 / 双指只改几何，**零延迟、零处理**；改规格立即重算取景框（复用已算好的 matte 与人脸点） |
| 头顶含发 | 用 alpha matte 在人脸横带内自上而下扫第一个有效前景行 = 真正的头顶（人脸框只到发际线，不含头发） |
| 预生成 | 按当前取景框裁剪 + 磨皮 + 合成，结果缓存进内存；带「取消」按钮与 15 秒超时 |
| 结果视图 | 只显示当前规格文字；背景色 / 磨皮可调（复用中间结果，300ms debounce 快速重算）；点图片全屏放大；下载 |
| 规格库 | 23 档，**每档独立 faceRatio（头部含发占比）/ centerY / topMargin**；支持自定义（mm 或 px） |
| 构图约束 | 头顶（含发）留白 ≥ topMargin（低于自动下拉）、下巴到画面下边 ≥ 10%，头顶绝不出框 |
| 换底 | **MODNet**（ONNX + onnxruntime-web，连续 alpha matte，发丝自然）→ 失败自动降级 MediaPipe Selfie Segmentation；含溢色去除与联合双边蒙版精修 |
| 磨皮 | 自写 WebGL 双边滤波，只作用于人脸椭圆；强度 0–30%（硬上限），平滑半径 1–5px |
| 校验 | 概要行常驻一行（✅ 符合规范 / ⚠ N 项警告 / ✗ N 项不通过），点击弹出浮层逐项列出六项检测，调参实时更新 |
| 导出 | JPEG 0.92→0.65 自动下调；目标大小（不限 / 20–40KB 学信网 / 40–100KB / 100–200KB） |

## 处理顺序

1. EXIF 方向矫正（`<img>` 解码，浏览器自动应用方向）
2. 人脸检测（Face Landmarker 468 点）
3. **整图 alpha matte**（MODNet，整张照片只跑这一次）
4. **头顶（含发）定位**：在人脸横带内自上而下扫 matte，第一个有效前景行即头顶
5. 裁剪框计算（读当前规格的 faceRatio / centerY / topMargin，叠加拖拽偏移与缩放，再做构图约束）
6. 【点「预生成」】按取景框裁剪 → 从整图 matte 采样出本裁剪的 alpha → 合成新底 → 磨皮
7. 【点「下载」】按规格原始像素跑同一套 6，并编码 JPEG

结果层（屏幕预览）长边 = 规格像素与「显示设备像素」的较大者，上限 1200；
交付层始终是**规格原始像素**（最大 1050×1500）。两层共用同一份 alpha，都不重跑模型。

原图先落到长边 ≤3600 的 master 画布（≈13MP），避开 iOS Safari 的 16MP 画布上限。

## 输出清晰度（曾经的大 bug）

旧实现为了「防锯齿」在 `renderCrop` 里做**多级折半降采样**：先 1:1 抠出裁剪区，再反复 `drawImage` 减半。
问题是 `drawImage(imageSmoothingQuality:'high')` 在降采样时**本身就会施加一次低通**，
链式折半等于把同一个低通反复卷积 —— 头发丝、衬衫纹理、毛孔就是这样整张糊掉的（不只是脸）。

实测（同一裁剪区、同一输出尺寸，拉普拉斯能量，越大越锐）：

| 实现 | 相对精确面积平均 | 相对单次 drawImage |
|---|---|---|
| 旧：多级折半 | 66%–78% | 71%–89% |
| **新：单次高质量重采样** | **94%–97%** | **100%（逐像素 max diff = 0）** |

修法：`renderCrop` 只画「裁剪框 ∩ 原图」一次，按面积映射到输出画布，中间不再有任何缓存步骤。
另外预览层改为按显示设备像素渲染（不再把 295×413 的图放大 2.8 倍显示在手机上）。

## 技术栈

- 零构建，纯静态 HTML / CSS / JS（IIFE + `window.IDP` 命名空间）
- 依赖全部走 CDN 并锁死版本：
  - `@mediapipe/tasks-vision@0.10.14`（jsdelivr 主 + unpkg 备，自动回退）
  - `onnxruntime-web@1.20.0`（MODNet 运行时；`numThreads=1`，不依赖 COOP/COEP）
  - `heic2any@0.0.4`（HEIC 转换，按需注入）
- 模型文件**本地同源托管**（`/models/`）：
  - `face_landmarker.task` 3.58 MiB（MediaPipe Face Landmarker 原版）
  - `modnet.onnx` 24.69 MiB（MODNet **fp32 原始 ONNX，未量化**）
  - `selfie_segmenter.tflite` 0.24 MiB（降级抠图）
  - 24.69 MiB < Cloudflare Pages 单文件上限 25 MiB（已用真实部署预检确认）
  - 原因：官方源是 `storage.googleapis.com` / `huggingface.co`，中国大陆不可直连
- **加载策略**：两个模型在启动页统一加载，并行下载、fetch + stream 实时进度；不依赖任何用户点击。
- `_headers` 给 `/models/*` 打 `Cache-Control: public, max-age=31536000, immutable`；
  `sw.js` 提供应用外壳预缓存 + 模型缓存优先 + 外部 CDN 运行时缓存，`VERSION` 常量管版本、自动清旧缓存。
  页面侧同时把下载好的模型写回 Cache Storage，二次访问模型**零网络请求**。

## 各规格构图参数

`faceRatio` = **头部（含头发）** 占画面高度的比例（头顶由 matte 扫出，下巴取关键点 152）；
`centerY` = 头部中心垂直位置；`topMargin` = 头顶（含发）最小留白。

| 规格 | faceRatio | centerY | topMargin |
|---|---|---|---|
| 一寸 / 小一寸 / 大一寸 / 二寸 / 小二寸 / 大二寸 | 0.68 | 0.42 | 0.05 |
| 驾驶证 / 三寸 / 四寸 / 五寸 | 0.68 | 0.42 | 0.05 |
| 身份证 / 中国护照 | 0.65 | 0.42 | 0.05 |
| 高考·学信网 | 0.66 | 0.45 | 0.06 |
| 美国签证 | 0.62 | 0.45 | 0.08 |
| 申根签证 | 0.75 | 0.42 | 0.05 |
| 日本 / 印度电子签证 | 0.68 | 0.45 | 0.05 |
| 韩国 / 澳大利亚签证 | 0.68 | 0.42 | 0.05 |
| 英国 / 加拿大 / 新加坡签证 | 0.66 | 0.42 | 0.05 |
| 自定义 | 0.68 | 0.42 | 0.05 |

取值依据对应证件的官方头高区间：身份证 / 中国护照 60–70%、美国签证 50–69%、申根 70–80%、其余 60–70%。

实测 23 档在各自默认参数下（短发 / 长发 / 蓬松大卷发三种测试图）：头顶（含发）留白全部 ≥ 规格值、
头部占比与规格误差 ≤0.03、下巴留白全部 ≥10%、头顶全部不出框。

## 磨皮参数

| 参数 | 取值 | 说明 |
|---|---|---|
| `sigma_space` | `radius × 0.6` | 规格给定；radius 1–5px，默认 3px |
| `sigma_color` | `0.08` | 强保边（≈20 灰阶），痣 / 疤 / 五官边缘不被跨越 |
| 强度 | 0–30% | 硬上限；映射到混合比例 ×3.33，≥28% 提示接近上限 |
| 级联 | 2 遍 | 单遍小核只够抹 1–2px 噪点，抹不动输出图上 5–9px 的真实痘痘 |
| `restore` | `0.85` | **频率分离的高频回填系数**（见下） |

### 为什么要做频率分离

毛孔是 1–2px、痘痘是 6–9px，尺度差 3–5 倍，**一个双边核区分不了**：靠「压掉 detail 层」去痘，detail 一压毛孔必然一起没。
实测（真实照片、脸颊同一块皮肤、二寸 418×586、22% / radius 3）：

| 配置 | 毛孔纹理保留 | 去痘 |
|---|---|---|
| `restore=0`（旧行为） | **41.8%** | 43.7% |
| **`restore=0.85`（当前默认）** | **96.2%** | 37.8% |
| `restore=1.0` | 112.4%（轻微过冲） | 37.3% |

做法：`out = mix(src, 双边, k) + hp × k × restore`，其中 `hp = src − 3×3 二项式低通`（1–2px 高频层）。
双边把痘（中频）连同毛孔（高频）一起抹掉，再把高频层按 `restore` 补回 —— **痘走掉、毛孔留下**。
级联对中频是乘法削减、对高频被 `restore` 抵消，所以两遍只加强去痘，不额外伤毛孔。

实测（二寸 413×579，注入已知幅度瑕疵逐像素测量，22% / radius 3）：

- 6px 痘痘淡化 **105%**、9px 痘痘 **16%**（均值 **60.7%**）
- 3px 痣 **−1.9%**、4px 疤 **8.9%**（均值 3.5%，即对比度保留 **96.5%**）
- 选择性 **17.1×**；斑心峰值几乎不动（痘 −5.3% / 痣疤 −6.8%）—— 结构还在，只是边缘变柔
- 五官强梯度保留 **100.9%**；脸部整体肤色 ΔE **0.13**；人脸椭圆外**逐像素零差异**

## 抠图：MODNet vs 标准

| 指标 | MediaPipe Selfie Segmentation | MODNet |
|---|---|---|
| 过渡带像素占比 | 1.05% | **10.58%** |
| 过渡带平均梯度 | 0.702（硬） | **0.170（柔）** |

> 口径说明：该表是**旧拉伸区间 0.03–0.97** 下的历史对照，用来说明两种引擎的软边量级差异；
> 现行拉伸 0.12–0.88 会把 MODNet 的软边整体收窄（见下节），但仍是标准引擎的十倍量级。

过渡带占比高一个数量级、梯度低一个数量级 —— 就是"发丝边缘自然、无锯齿"的量化表现。

### 边缘灰晕（"轮廓糊"）的成因与修法

MODNet 给出的 matte 过渡带偏宽，半透明像素把**原背景（浅灰墙）**一起带进新背景，
于是在整个头颅/肩膀轮廓外形成一圈灰色晕影 —— 观感就是"边缘糊"。

| 项 | 旧 | 新 | 说明 |
|---|---|---|---|
| matte 对比度拉伸 | `0.03 – 0.97` | **`0.12 – 0.88`** | 收窄半透明带 |
| 头发上缘过渡带 | 20.0 原图 px | **15.0 px** | 收窄 1.33× |
| 脸颊轮廓过渡带 | 15.0 原图 px | **10.0 px** | 收窄 1.50× |
| 软像素占比 | 1.85% | 1.11% | 仍保留真实飞发 |

再窄到 `0.20 – 0.80` 能到 10.0/7.5 px，但飞发被削光、发际像剪出来的，故不采用。

**去溢色也修了一处数学错误**：观测像素本身已经是「前景 × α + 原背景 × (1−α)」，
旧代码把它**再乘一次 α**，等于前景变成 α²F —— 发丝边缘被再压淡一层。
现改为对着**邻近原背景色**反解前景真色 `F = obs + (obs − B_bg)·(1−α)/α`，
再合成到新背景（`spill = 0.85`，`spillMinA = 0.12` 防低 α 处放大噪声）。
注意：不能拿"邻近前景色"当反解基准 —— 那等于把发丝往实心头发上拽，边缘同样会整体变淡。

### 试过但不采用
提高 MODNet 输入分辨率（短边 512→1024、长边 1024→2048）：过渡带只从 20.0 收到 17.5 px（1.14×），
分析耗时却从 7.5s 涨到 21.6s（2.9×），不划算。

## 合规结论三级

- **通过（绿 ✓）**：正常下载
- **警告（橙 !）**：可下载，带提示
- **不通过（红 ✕）**：下载置灰 + 内联修正提示（保留一个低对比度「仍要下载」逃生口，避免因判定失败彻底卡死）

## 本地运行

```bash
cd IDPhoto
python -m http.server 8899
# 打开 http://127.0.0.1:8899/
```

（不能用 `file://`：模型与多段脚本需要同源。）

## 部署

零构建，推送即部署。仓库推送到 `main` → GitHub Actions（`.github/workflows/deploy.yml`）调用 `cloudflare/wrangler-action` 做 Pages Direct Upload。

```bash
npx wrangler pages deploy . --project-name=id-photo --branch=main
```

需要仓库 Secrets：`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`。

> 本项目使用 Cloudflare Pages **Direct Upload**（非 Git 集成）——该账号未安装 Pages 的 GitHub App，无法用 API 建 Git 集成项目。效果等同：push 后约 30–40 秒自动上线。
